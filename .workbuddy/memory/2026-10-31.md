## LOD 远景纯白色 → 真实地形色管线移植（Voxy 思路）

### 背景
LOD 已能渲染（前几轮探针/矩阵/顶点全部验证通过），但远景地形**纯白色**——
因为 `LODChunk.surfaceIds` 硬编码为 0，`GreedyMesher` 顶点颜色写死 `0xFFFFFFFF`。

### 本次做的事
将 Voxy 的 "BlockState → MapColor → Palette → GreedyMesh" 管线移植到本地，
彻底用真实地形色替代伪白。

### 改动清单
1. **新增 `lod/data/LODColorPalette.java`**：全局 ARGB→索引调色板，`Int2IntOpenHashMap`
   上限 256 色，溢出按 RGB 欧氏距离合并最近色（不丢弃）。`intern()` synchronized，
   `colorAt()` 无锁。
2. **新增 `lod/io/BlockStateColorExtractor.java`**：反射读 `BlockStateBase.mapColor`
   字段得静态默认 MapColor（绕过 `getMapColor(BlockGetter,BlockPos)` 的生物群系染色
   NPE 风险），`MapColor.col | 0xFF000000` 得 ARGB。
3. **`LODChunk.java`**：`surfaceIds`→`colorIndex`（byte），删除硬编码 0，`create()`
   新增 `surfaceColorIdx` 参数；`surfaceIdAt`→`colorIndexAt`。
4. **`McaRegionReader.java`**：新增 `extractSurfaceColorIndex()`，遍历
   `sections[].block_states`，用 `BlockState.CODEC.parse(NbtOps, entry)` 解析 palette，
   找每列最高非空气方块，`readPacked()` 读位打包体素索引。
5. **`GreedyMesher.java`**：合并条件 `surfaceId`→`colorIndex`，顶点颜色
   `colorPalette.colorAt(sid)`，侧面 quad 取高侧列颜色，删除 `SURFACE_COLOR` 白。
6. **`lod_terrain.json`**：`attributes` 补 `Color`（此前缺失 → `in vec4 Color`
   属性绑定失败，是颜色异常的隐患）。

### 关键 API（javap 反编译确认）
- `MapColor.col`（`public final int`，ARGB，R 在 bits16–23）
- `Block.BLOCK_STATE_REGISTRY`（`IdMapper<BlockState>`）
- `BlockState.CODEC`（`Codec<BlockState>`，解析 `{Name,Properties}`）
- `BlockStateBase.mapColor`（`private final MapColor`，静态默认色）
- NeoForge 1.21.1 **无** `getDefaultMapColor()`（用户提到的 API 名不存在，用反射替代）

### 阻塞
1. **Voxy 仓库不可达**：`caili007/VoxelsStructure` 返回 `Repository not found`，无法给出行号参考。
   改用 MC 原版 MapColor/BlockState API 等价实现。
2. **gradle 构建网络阻塞**：`maven.neoforged.net:443` TCP 超时（buildSrc userdev pom HEAD），
   与代码无关。javac 独立编译（+fastutil/slf4j/datafixerupper）**0 错误**。

### 交付

- 待用户本地 `./gradlew build` 后进游戏验证远景色。

## LOD 原生管线重构（解决光影消失 + 原版渲染破碎）

### 背景
用户诊断两个致命问题：①开启 Iris 后 LOD 消失（自定义 28 字节 VBO 布局不符合
`DefaultVertexFormat.BLOCK`，GBuffer/Shadow Pass 读不到 UV/Lightmap/Normal）；②原版
视角远处地形"辐射条带/破碎豆腐块"（裸 OpenGL 绘制，无深度排序/批次合并）。

### 改动清单（7 处）
1. **`LODMesh.java`**：顶点布局严格对齐 `DefaultVertexFormat.BLOCK` 32 字节
   （Position12+Color4+UV0 8+UV2 4+Normal 3+pad1），修正 28→32 字节笔误与注释。
2. **`GreedyMesher.java`**：UV 从 `UV_CENTER=0.5` 改为**世界坐标平铺**（x→u, z→v,
   侧面 y→v），法线 6 面朝向已正确（叉积逐一验证 CCW）。
3. **`LODVboUploader.java`**：VBO 格式 `POSITION_COLOR`→`DefaultVertexFormat.BLOCK`，
   模式 `TRIANGLES`→`QUADS`，新增 `emitBlockVertex()` 完整写入
   `setColor/setUv/setUv2/setNormal` 五属性（此前丢 UV0/UV2/Normal 是光影消失根因）。
4. **`LODShaderRegistry.java`**：shader 注册格式 `POSITION_COLOR`→`BLOCK`。
5. **`LODRenderEventHandler.java`**：渲染提交从裸 `RenderSystem.enableDepthTest/depthFunc`

   移除 ModelViewStack 操作（1.21.1 无 PoseStack 语义，`drawWithShader` 用显式矩阵）。
6. **`lod_terrain.vsh/.fsh/.json`**：shader 属性声明升级为 BLOCK 五属性
   `Position/Color/UV0/UV2/Normal`，仍纯色输出（MapColor，不采样纹理）。
7. **`scripts/verify_lod_compile.ps1`**：编译验证脚本改 corretto-22（英文路径）+ raw.jar + fml/bus。

### 关键 API（javap 反编译确认）

- `RenderType.solid()` + `RenderStateShard.setupRenderState()/clearRenderState()`（public）

## 渲染管线重构 + 远景穿插/远切修复（第二次任务）

### 用户任务（三项修复）
1. 强制关背面剔除：`setupRenderState()` 后加 `disableCull()`，`clearRenderState()` 后 `enableCull()`。
2. 远切：按区块中心到相机距离过滤，超出视距直接 return 跳过，不交 GPU 硬件裁剪。
3. Alpha 检查：确认 VBO Alpha=255 固体；半透明才需 VertexSorting。

### 改动
- `Config.java`：新增 `LOD_VIEW_DISTANCE_BLOCKS`（视距上限，默认 4096 格，范围 256~65536）+ `getLodViewDistanceBlocks()`。
- `LODMesh.java`：新增 `centerX()/centerZ()`（区块中心世界坐标）。
- `LODRenderEventHandler.java`：
  - `setupRenderState()` 后 `RenderSystem.disableCull()`，`finally` 里 `enableCull()`。
  - 提交循环内按 `(centerX-camX)^2+(centerZ-camZ)^2 > viewDist^2` 跳过（CPU 侧远切）。
  - 诊断日志新增 `远切=` 和 `viewDist=` 字段。

### 关键结论
- 日志 `prog=0` 是**假警报**：诊断代码在 `VertexBuffer.unbind()`/`drawWithShader` 结束后才读 `GL_CURRENT_PROGRAM`，此时 shader 已被 clear，恒 0 正常，非 bug。
- 地形穿插/硬切根因：上一轮改用 `RenderType.solid().setupRenderState()` 引入了背面剔除（CULL），LOD 低模绕序任一面偏差→面片消失→穿插。本次 disableCull 解决。
- Alpha 已确认 255 固体（MapColor.col 的 ARGB 恒 0xFF），走不透明通道，无需 VertexSorting 半透明排序。

### 编译验证
- `RenderSystem.disableCull()/enableCull()` 已 javap 确认存在。
- 核心文件（LODMesh/Config/GreedyMesher/LODVboUploader）编译，唯一报错是既有 `Config→Ribbon→其他子模块` 依赖链（Ribbon.MODID 常量引用 entityculling/music/pathfinding 等），非本次改动问题。

## LOD 性能优化 + 渲染状态修复（第三次任务）

### 用户任务（三项：慢/乱/Iris）
1. 极致优化生成性能：异步化、对象池、批量提交、降低精度。
2. 修复渲染状态与穿插：强制深度写入、关背面剔除、视锥剔除、远切平滑。
3. Iris 兼容与调试：gbuffer fallback、单帧耗时日志。

### 改动
- **新增 `LODMeshPool.java`**：LODMesh 对象池，复用回收的 DirectByteBuffer（32KB/个），
  杜绝玩家移动时频繁 `ByteBuffer.allocateDirect`（JNI 昂贵 + 触发 Full GC）。
  `acquire()` 优先取空闲 buffer，`release()` 归还（容量标准才复用，上限 256）。
- **`LODMesh.java`**：新增 `wrap(reusedBuffer, cap)` 静态工厂 + `detachBuffer()` 包私有方法；
  `recycle()` 改为通过池归还 buffer（原来只 clear 直接丢 GC）。
- **`LODManager.java`**：
  - `requestLOD` 改用 `LODMeshPool.getInstance().acquire()` 替代 `LODMesh.acquire(32KB)`。
  - 新增 `buildAccumulator`/`builtCount` 原子统计，`drainBuildAvgMs()` 返回单区块平均构建耗时。
  - `stop()` 里 `LODMeshPool.clear()` 释放空闲直接内存。
- **`LODRenderEventHandler.java`**：
  - `setupRenderState()` 后显式 `enableDepthTest() + depthMask(true) + depthFunc(LEQUAL)`（不依赖隐含状态）。
  - 心跳日志新增 `buildAvgMs`（单区块构建耗时，超 10ms 报警）和 `pool`（池空闲数）。

### 关键结论
- 对象池是"慢"的根因解药：`allocateDirect(32KB)` 是 JNI 调用，玩家移动时每区块一次，
  高频触发 Full GC 和 Direct buffer 压力，导致生成断断续续。
- `ready=1024` 满 + `inFlight=0` = 生成已跑完但缓存满，`requestLOD` 的 `readyMeshes.size()>=MAX` break 是保护性上限，配合 evictFarAway 每帧淘汰可自我平衡。
- 雾效渐变：lod_terrain.fsh 已有 `linear_fog(vertexColor, vertexDistance, FogStart, FogEnd, FogColor)`，
  但 `drawWithShader` 不设置 fog uniform（只用 json 默认 FogStart=0/FogEnd=1），远景雾几乎失效。
  这是"地平线硬切"的残余原因（远切 CPU 侧已做，但雾未渐变）。
- Iris：自定义 BLOCK shader 未声明 gbuffers_terrain fallback，靠 `allowUnknownShaders` 绕过；
  切回 RenderType.solid() 会引入纹理采样（纯色 LOD 无 atlas UV），得不偿失，保持自定义 BLOCK shader。

### 编译验证
- `LODMesh.java + LODMeshPool.java` 单独 javac exit=0（对象池核心代码正确）。
- `RenderSystem.disableCull/enableCull/depthMask/depthFunc` 均已确认存在。
- GreedyMesher 引用 `Config` 是既有依赖，非本次改动。

## 第十轮：修复颜色红蓝互换 + 光影黑灰噪点（18:01 追加）

### 用户反馈（三张截图）

### 根因一（颜色字节序，铁证）
反编译 `MapColor.java` 确认 `MapColor.col` 是 **ABGR**（低字节=R，高字节=B），
`calculateRGBColor` 返回 `0xFF000000 | l<<16 | k<<8 | j`（l=col&0xFF→R，j=col>>16→B）。
而 `BlockStateColorExtractor.desaturate()` 误按 **ARGB** 解析（`r=argb>>>16` 实为 B、`b=argb&0xFF` 实为 R），
导致**红蓝通道互换**：水体(高蓝低红)→橙红、沙土/恶地(高红低蓝)→蓝紫。这是"饱和度/颜色怪异"根源。

### 根因二（光影黑灰噪点）
AFTER_LEVEL 阶段（deferred 已结束）LOD 用 LEQUAL 深度测试，对比的是 Iris composite 重建的
深度缓冲（内容与 LOD 几何无关，甚至含垃圾值）→ 大量像素深度测试失败 → 黑斑 + 雪花噪点。

### 修复
1. **BlockStateColorExtractor.desaturate()**：改按 ABGR 解析（r=低字节，b=高字节），
   DESATURATION 0.35→0.25、BRIGHTNESS 0.88→1.0（取消额外压暗，用户反馈偏灰偏暗）。
2. **LODRenderEventHandler**：光影路径（AFTER_LEVEL）改为 `disableDepthTest + depthMask(false)`
   + `enableBlend + blendFunc(ONE,ZERO)`（强制不透明），LOD 一律绘制不被旧深度剔除；finally 恢复。
3. **lod_terrain.fsh**：alpha 强制 1.0（不用 vertexColor.a，杜绝 MapColor 高位非 0xFF 的 alpha 异常）；
   雾 FOG_START 200→256、FOG_END 1200→1400；删除无用的 upFacing 死代码。
4. **lod_terrain.vsh**：去掉 `#moj_import <fog.glsl>` 和 `fog_distance()`，改用 `length(viewPos.xyz)`
   直接算相机距离（消除 fog.glsl 内部 FogStart/FogEnd/FogColor uniform 缺失的隐患）。
5. **lod_terrain.json**：移除 FogShape uniform（vsh 不再用）。

## 第十四轮：修复 LOD 自定义 uniform 时机 bug（19:02 追加）

### 核心 bug（本轮修复）
`VertexBuffer.drawWithShader()` 内部顺序是 `setDefaultUniforms → apply() → draw → clear()`。
`apply()` 会把**所有 uniform 重置为 json 默认值并上传**，覆盖掉 `applyQualityUniforms()`
提前设置的 `QualityMode/Sampler0/sprite UV`。导致 HIGH 档（atlas 采样）的 uniform 被
apply() 重置 → 纹理采样失效/颜色错乱。

### 修复
`LODRenderEventHandler.java` 的 draw 循环改为手动复刻 drawWithShader 三步，把自定义
uniform 放在 apply() 之前：
```
setDefaultUniforms(QUADS, fullView, projection, window)  // 设矩阵 + 默认 12 sampler
applyQualityUniforms(shader, mc)                          // 覆盖 Sampler0=atlas、QualityMode、sprite UV
shader.apply()                                            // 一次性上传全部 + 绑定 sampler
vb.draw()
shader.clear()
```

### 诊断改进
- `[prog]` 行改为在 **apply() 之后、draw() 之前** 读 GL_CURRENT_PROGRAM（这才是 shader
  是否真正绑定的铁证，非 0 = 生效，0 = 被 Iris 拦截）。旧代码在 draw 后读恒 0 是假警报。
- `[提交]` 行移除无意义的 prog 字段。

### 关键 API 确认（反编译 VertexBuffer/ShaderInstance）
- `VertexBuffer._drawWithShader` = `setDefaultUniforms → apply → draw → clear`（铁证 uniform 被覆盖）
- `ShaderInstance.setDefaultUniforms(VertexFormat.Mode, Matrix4f modelView, Matrix4f proj, Window)`
  （参数名有误导，实际第2参赋 MODEL_VIEW_MATRIX、第3参赋 PROJECTION_MATRIX）
- `ShaderInstance.apply()` = 遍历 samplerMap bindTexture + 遍历 uniforms upload（所以自定义
  uniform 必须 apply 前设好）
- `setSampler(name, Object)` / `Uniform.set()` 都 markDirty，需 apply 才 upload

## 第十五轮：修复转化罢工 + 光影颜色错乱（19:20 追加）

### 用户需求

### 核心 bug 修复（转化罢工根因）
**LODManager.requestLOD 的「readyMeshes.size() >= MAX_READY_MESHES(4096) 直接 break」**
- 日志铁证：`ready=4096`（满）、`inFlight=0`、`buildAvgMs=n/a`（整个 session 零构建）
- 根因：玩家移动后渲染线程 evictFarAway 淘汰旧网格，但请求端（tick 阶段，早于渲染帧）
  看到缓存仍满直接 break，新区域永远进不了构建队列 → LOD 环带无法更新
- 修复：requestLOD 不再用 readyMeshes.size() 做硬 break，只受 inFlight 约束；
  readyMeshes 上限交给渲染线程 evictFarAway（每帧）+ drainReady 满上限丢弃维护

### 判定奇怪修复（"落下又变成 LOD"）
1. **内圈过滤缺失**：渲染端 cullToFrustum 后没按 innerRadius 过滤，进入原版渲染距离内
   的 LOD 网格仍被提交，与原版区块重叠绘制。修复：visible.removeIf 跳过内圈（Chebyshev）
2. **新增 evictInner**：淘汰玩家内半径内遗留的 LOD 网格（曾经在外圈、玩家靠近后进入
   原版接管区），释放缓存
3. **圆形→方形判定对齐**：原版渲染是方形，之前用 dx²+dz² 圆形判定导致四角 LOD 与原版
   重叠。MixinLODLifecycle + evictFarAway 统一改为 Chebyshev 距离 max(|dx|,|dz|)
4. **先淘汰后收割**：onRenderLevel 里 evictFarAway/evictInner 移到 drainReady 之前，
   先腾位再放入新网格，避免 drainReady 满上限 recycle 丢弃新构建网格
5. **节流默认值 20→5 tick**：减少玩家移动后 LOD 更新滞后

### 光影颜色错乱（灰黑偏暗 + 橙红锈色）
- 反编译 Iris 1.8.12 确认：`MixinShaderInstance.onTail()` 拦截条件 = shouldOverrideShaders()
  = `isRenderingWorld && isMainBound`（IrisRenderingPipeline 两字段 AND）。
  AFTER_LEVEL 阶段 isRenderingWorld 已 false → 不拦截，LOD shader 正常 draw（draw=1024 glErr=0）。
- 结论：光影下 LOD 渲染通路是通的，问题纯粹是**颜色**（不是通路拦截）
- 修复：lod_terrain.fsh 新增 ShaderMode uniform，光影下（ShaderMode=1）不做方向光照、
  不叠固定雾色（仅极轻距离雾），避免 deferred 已处理后双重处理导致偏暗偏色
- Java 端 applyQualityUniforms 传入 irisRendering 设置 ShaderMode

## 第十六轮：颜色失真 + 夹缝 + 光影颜色错乱 三线修复（19:50 追加）

### 用户需求
1. 无光影时正常区块和 LOD 之间有夹缝
2. 光影时呈现不同的错误美术效果（颜色错乱/黑块）
3. 继续反编译 iris/sodium 让 ribbon 获得兼容层；枚举其他 bug

### 核心根因定位（反编译铁证）

**A. 颜色发灰/发棕/橙红锈色（无光影 LOD 与近景脱节）**
- `MapColor.GRASS = 0x007FB238`（灰绿）等是"未染色基础色"，原版草方块渲染时经
  `Block.getMapColor` 做生物群系染色才变鲜绿。Ribbon 离线读 `BlockStateBase.mapColor`
  字段拿到的是未染色基础色 → 无法染色（无 BlockGetter）→ 灰暗。
- 叠加因素：`directionalLight` 基线 0.62（侧面偏暗）+ `FOG_START=256` 过早（雾把
  LOD 混灰）+ CPU 端去饱和 0.12。
- 修复：去饱和 0.12→0；光照基线 0.62→0.82；FOG_START 256→512、FOG_END 1400→1800、
  FOG_COLOR 提亮（0.78,0.84,0.92）。

**B. 无光影夹缝（核心 bug，反编译 Embeddium 铁证）**
- `RenderSectionDistanceFilter.DEFAULT = (dx²+dz² < maxDistance²) && |dy|<maxDistance`
  → 原版 Embeddium 渲染距离是**圆形（欧氏距离）**，非方形！
- 上一轮把 LOD 内圈过滤/请求/淘汰全改成了方形 Chebyshev，导致四个角落
  「LOD 跳过 + 原版圆形渲染未覆盖」→ 真空夹缝。
- 修复：请求端(MixinLODLifecycle)、渲染端内圈过滤、evictFarAway、evictInner 全部
  改回欧氏距离圆形判定，与原版严格对齐。

**C. 光影颜色错乱（AFTER_LEVEL 画到最终 sRGB framebuffer）**
- 反编译确认：`finalizeLevelRendering()` 置 isRenderingWorld=false，AFTER_LEVEL 在
  final pass 之后，主 framebuffer 已是 sRGB 编码输出。
- ShaderMode==1 分支之前还叠了 `lightFog = fog*0.85` 的固定灰蓝雾 → 发灰。
- 修复：ShaderMode==1 改为**直接输出纯顶点色**（albedo，不混雾不调光），颜色空间
  交给光影 final pass 已处理的结果。
- 光影深度：之前 `clear(GL_DEPTH_BUFFER_BIT)` 清掉近景深度 → LOD 无视遮挡画在最上层
  与近景穿插。改为**不清深度**，用现有近景深度做 LEQUAL，让近景正确遮挡 LOD。

**D. 存档损坏区块反复重试刷屏**
- 日志大量 `stream truncated / external chunk not file / negative size`（世界"新的世界"
  存档损坏），`requestLOD` 读取失败后 inFlight.remove，5 tick 后又被请求 → 反复读盘
  刷屏 + 永久黑洞。
- 修复：新增 `failedCooldown` 表（30s 冷却），读取失败区块冷却期内不重试。

### 关于"让 ribbon 获得兼容层"的结论
反编译 `IrisLodRenderProgram` + `DHCompat` 确认：DH 的光影兼容靠光影包提供
`dh_terrain` program（ProgramSource）+ `com.seibel.distanthorizons.api.DhApi`（MethodHandle
反射）。Ribbon 无法复制（无 DH API、光影包无 dh program）。务实路径仍是 AFTER_LEVEL
直接画 + ShaderMode 简化颜色（本轮已完善）。
