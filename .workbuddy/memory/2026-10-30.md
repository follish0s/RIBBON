# 2026-10-30 工作日志

## LOD 不可见排查：加「全屏红三角探针」做渲染目标层二分定位

### 背景
历经十几轮，LOD 矩阵/顶点/雾/字节序/视锥全部验证正确，`draw=N` 成功但屏幕始终看不到，
开/关光影都看不见。用户判断：Ribbon（Embeddium 分支）把世界渲染进自管离屏 framebuffer，
诊断里的「主 FB=2」可能不是最终上屏那张，导致像素从未上到最终屏幕。

### 本次做的事（严格按用户要求，只做一件）
在 `AFTER_TRANSLUCENT_BLOCKS` 同一时机、同一 draw 路径，新增**探针 shader + 全屏红三角**，
绕开 mesh 数据 / 剔除 / 矩阵 / 雾 / 光照一切变量，判定像素到底有没有上屏。

### 改动清单
1. 新增探针 shader 三件套（`assets/minecraft/shaders/core/lod_probe.{json,vsh,fsh}`）：
   - `lod_probe.vsh`：`gl_Position = vec4(Position, 1.0)`（顶点直接是裁剪空间坐标，不做任何矩阵变换）
   - `lod_probe.fsh`：`fragColor = vec4(1,0,0,1)` 写死纯红
   - `lod_probe.json`：attributes 只有 `Position`（POSITION 格式 = 12 字节/顶点）
2. `LODShaderRegistry.java`：注册探针 shader（`DefaultVertexFormat.POSITION`），加 `getProbeShader()`。
3. `LODRenderEventHandler.java`：
   - 新增 `PROBE_ENABLED = true` 开关、`drawProbeFullscreenTriangle()` 方法。
   - 探针方法：用 Tesselator 上传 3 顶点红三角 VBO（裁剪空间坐标 (-1,-1,0.5)/(3,-1,0.5)/(-1,3,0.5)），
     深度设 GL_ALWAYS + 不写深度（无视一切遮挡），单位矩阵 drawWithShader。
   - draw 前 glGet 实测 GL_FRAMEBUFFER_BINDING / GL_SCISSOR_BOX / GL_COLOR_WRITEMASK / GL_BLEND
     / GL_DEPTH_WRITEMASK / GL_DEPTH_FUNC + 紧跟 glGetError，**每帧持续打印 240 帧（约 4 秒）**。
   - 探针期间短路后续正常 LOD 渲染（`if (PROBE_ENABLED) return`）。

### 编译坑（记录）
- `return;` 后保留原 LOD 代码会触发「无法访问的语句」编译错误。解决：用 `boolean PROBE_ENABLED`
  常量包 `if (PROBE_ENABLED) { drawProbe(); return; }`，后续代码语法可达。

### 判定分支（待用户测试）
- 整屏变红 → 时机+shader+当前缓冲+状态能出图，问题在 mesh 坐标/顶点格式/剔除侧。
- 一点不红 → 像素从未上屏，锁定渲染目标层，查 Embeddium 自管离屏 FB 是否真为 FB=2 及 blit 来源。

### 顺手确认的潜伏 bug（用户点出，未改）
shader 注册为 POSITION_COLOR 但顶点 buffer 每顶点只有 12 字节（仅 POSITION 无 COLOR），
color 属性拿不到数据，可见后会是黑/乱色——待探针定位后补 COLOR 属性或改注册为 POSITION。

## 探针结果 + 修复1/修复2（第二轮）

### 探针结果（用户反馈）

DepthWriteMask=0、DepthFunc=519、glError=0，全部干净。问题锁定在 mesh 侧。

### 字节码级铁证（本轮反编译）
1. `VertexBuffer._drawWithShader`：`setDefaultUniforms(mode, aload_1[=modelView], aload_2[=projection], window)`
   —— 传入的第一个矩阵参数直接作为 ModelViewMat，**没有**用 RenderSystem.getModelViewMatrix()。
2. `DefaultVertexFormat.POSITION_COLOR` = Position(F32×3=12) + Color(U8×4=4) = **16 字节/顶点**；
   `POSITION` = 12 字节/顶点。
3. joml 1.10.5 `Matrix4f.translate`：`_m30 = fma(m00,x, fma(m10,y, fma(m20,z,m30)))` = 更新第 4 列
   = `this·T(x,y,z)`（右乘）。故 `fullView = modelView·T(-cam)` = R·T(-cam) = 正确 view 矩阵。
4. 手算验证：帧#100 modelView（纯旋转，m03/m13/m23 全 0）+ 相机，前方 100 格点经 fullView
   变换得 v_view=(0.05,-0.01,-100.06)，z<0 前方、长度守恒 100.06 → **矩阵数学完全正确**。

### 结论：修复1 的假设（shader 收到不含平移 modelView）在当前代码不成立
代码第 267 行早已传 fullView，且字节码证明 drawWithShader 正确使用它。但仍按用户要求加了
运行时诊断打印，用事实说话。

### 本轮改动
1. **修复2（顶点格式）**：LOD 统一改为 POSITION（12字节）：
   - `LODVboUploader`：`begin(QUADS, POSITION)` + `addVertex(x,y,z)`（去 setColor）
   - `LODShaderRegistry`：注册改 `DefaultVertexFormat.POSITION`
   - `lod_terrain.json`：attributes 只剩 Position，删 ColorModulator uniform
   - `lod_terrain.vsh`：删 `in vec4 Color`，vertexColor 写死白
   - `lod_terrain.fsh`：颜色写死亮绿 `vec4(0,1,0,1)`（验证可见性，确认后恢复真实色）
2. **修复1（诊断）**：drawWithShader 前打印 fullView 的 m03/m13/m23 对比 -camPos；
   加首顶点 fullView×proj 后的 NDC 坐标诊断。
3. `PROBE_ENABLED` 改回 false（恢复正常 LOD 渲染路径，探针红三角短路关闭）。

### 待用户测试
预期看到**亮绿色** LOD 地形剪影（颜色写死绿，与探针红区分）。日志看「修复1·矩阵平移」和

## 关键判断分歧：顶点是"世界坐标"还是"局部坐标"？（第五轮）

### 用户判断
看到绿三角悬在相机前方 8 格，判断"LOD mesh 顶点存的是局部坐标，被 shader 当世界坐标画在
相机附近，其他 mesh 偏出屏幕"。要求加原点偏移（方案A改上传 / 方案B改shader）。

### 我的代码证据（反驳）
1. **那个绿三角是探针三角形，不是真实 LOD mesh**。上一轮 `WORLD_TRIANGLE_PROBE=true` 故意
   构造了 cam+forward*8 的探针三角形，顶点设计上就在相机前方 8 格。用户把它误认成
   "某个 LOD mesh 从局部原点画到了相机前"。
2. **真实 mesh 顶点是世界坐标（日志铁证）**：
   - GreedyMesher 第 138 行 `emitTopQuad(mesh, baseX + x, baseZ + z, ...)`，baseX = chunk.worldMinX()
   - 日志 `[写入验证] 首顶点 世界=(-544.0,63.0,448.0)`，区块(-34,28)→ x=-34*16=-544 ✓
   - 日志 `[诊断] 区块(6,10) 首 quad x=[96,112]` = 6*16=96 ✓
   - LODChunk.worldMinX() = SectionPos.sectionToBlockCoord(chunkX) = chunkX*16 ✓
   顶点坐标 100% 是世界坐标，**再加偏移会双重偏移**。

### 字节码级铁证（本轮反编译，彻底排除 QUADS 索引变量）
1. `Uniform.set(Matrix4f)` → `matrix.get(FloatBuffer)` → joml 列主序输出 → GL mat4 平移列正确。
   joml translate 写 m30/m31/m32，get(FloatBuffer) 列主序输出时落到 GL 第4列，链路正确。
2. `Mode.indexCount(QUADS)` → `vertexCount/4*6`（每 quad 转 2 三角形）
3. QUADS `asGLMode=4=GL_TRIANGLES`（构造参数 (name=QUADS, ordinal=7, asGLMode=4, vertsPerPrimitive=4)）
4. `uploadIndexBuffer` 对无显式索引的 QUADS 调 `RenderSystem.getSequentialBuffer(mode)` 生成
   AutoStorageIndexBuffer 顺序索引 0,1,2,2,3,0，`bind(indexCount)` 绑定容量。
   → QUADS 渲染链路在 MC 1.21.1 完全正确，不是问题。

### 本轮改动（收敛，等待真实数据）
1. `WORLD_TRIANGLE_PROBE` 改回 **false**（让真实 LOD 跑起来，mesh 侧诊断才能执行）。
